## 2. Addendum

### A-1 — P5-K11 wiring supersedes brief §12's venue proposal; job-name and protection posture CONFIRMED untouched
Brief §12's header proposes a new suite home `tests/sim-npc.test.ts` and a **new** non-required CI job `NPC core tests (non-required)`, and brief §13 speaks of an "NPC core job" and four green jobs. **None of that governs.** Under **P5-K11** (Petra prep §1, adopted — the QA annex's wiring over the brief's proposal, following the Phase 4 play-core precedent), the venue of record is:

- Suite file: **`tests/npc-core.test.ts`**, added to the **existing** `Sim core tests (non-required)` job's command, inside the `emulators:exec` segment alongside `tests/sim-core.test.ts` and `tests/play-core.test.ts` (the NPC suite drives the real envelope queue + dispatcher + Situations substrate against the emulator; it is not a pure-logic harness).
- Job display names after the Phase 5 PR are exactly the three that exist today: **`Install · Typecheck · Lint · Build`**, **`Rules tests (non-required)`**, **`Sim core tests (non-required)`** — plus the Vercel preview check. No job is added, renamed, or removed.
- Branch protection is **not modified** by the Phase 5 PR: `Install · Typecheck · Lint · Build` remains the **only** required context. Neither emulator job is promoted, and nobody ticks a `(non-required)` context in the protection UI — promotion follows only the standing separate path (≥3 consecutive green push-triggered runs on unmodified master + the checklist, per the rules-promotion-evidence precedent).
- Brief §13's merge condition therefore reads: **required check + Rules + Sim core (incl. the NPC suite) + Vercel preview, all green.** Any build document citing an "NPC core job" means the NPC suite inside the Sim core job.

### A-2 — P5-K10 production identity: every row closes "built, not live"; no row certifies production operation
Phase 5's runner is the first consumer that cannot go live without the production fabric identity (Petra prep §3). The gate's claim fixtures (`fabricCommitter`/`fabricWorker` contexts) are emulator fixtures. Accordingly:

- **Every row P5-G1–P5-G13 closes on CI evidence in built form.** No row's evidence touches production, and no row may be reported — in the PR, the gate record, or any summary — as passing "live."
- The rows whose live form exercises the production identity are named so the caveat is checkable rather than atmospheric: **P5-G1** (fabric cycles), **P5-G8** (worker claim/lease/crash behavior), **P5-G9** (committer fences), **P5-G12** (wake-created Situation). For these rows the gate certifies the built behavior against emulator claim contexts only; the same behavior against the production service user is certified by nothing in this gate.
- The production chain (P5-K10 / P2-K15) is **not a gate row** and the gate does not block on it. The chain, in order: (1) production fabric service user provisioned with the `fabric` claim and **both** `fabricRole` values (`committer` and `worker`); (2) production rules deploy of the full post-Phase-5 rules file; (3) production indexes deploy; (4) production genesis executed; (5) an operated production wake path. If at Phase 5 merge the chain is unexecuted or its owner unassigned, the **PR body must state Phase 5 is "built, not live" and name the five items** (Petra prep §3 formulation). Gate closure with that statement in the PR is a full closure of this gate — and a standing, named debt, not a pass on liveness.
