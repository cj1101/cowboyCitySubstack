### P5-D6 — Effective-version immutability vs undo: FLAGGED FOR KODA RATIFICATION — recommended reading stated, NOT adopted here
Dana's wording ("version docs never updated or deleted after effectiveness") and CJ's Log ruling (undos erase, with dependency checks) collide on mandate and delegation-rule versions. **Recommended reading — adopt brief §9.8 as written:** inside an undo restore transaction only, fabric restores the root's version pointer and flips the superseded version's status; version payloads never edited. In full: (a) inside an undo restore transaction (§8.5 discipline) and nowhere else, the fabric restores the mandate/rule root's current-version pointer to the pre-resolution value; (b) inside that same transaction, the fabric flips the superseded version's status back — the version **payload is never edited**, by anyone, ever; (c) versions that never became effective (still `pending`) are deletable by their author through the ordinary action flow; (d) effective versions are deletable by **no** identity outside a restore transaction. Rationale: this is the Phase 2 D-1 pattern (erasable-with-dependency-check) applied to a new collection; Dana's absolute wording governs *ordinary writes*, and CJ's ruling is the higher authority on erasure — the amendment is stated in the open here rather than smoothed into either source. This record does **not** adopt it: Koda ratifies at PR review. Dana + Osei's pending audit-export sign-off (P2-K9 follow-up) should note the interaction, since a restored pointer is exactly the kind of fact an audit export must represent content-free. If Koda judges D6 CJ-sized (it interprets his erasure ruling against Dana's immutability wording), it becomes a one-line War Room note; the build is not blocked either way, because §9.8's fence is the only implementation either reading produces — the readings differ on *deletion inside restores*, which the gate can assert either way once ratified.
**Gate consequence (countersign A-7) — this flag is load-bearing for the Phase 5 PR, and stays flagged exactly as above:** P5-G9 asserts version immutability including against the committer, with brief §9.8 fencing the one lawful exception. The gate can assert either D6 reading, but it must assert the **ratified** one: the fixture's deletion-inside-restore assertion is pinned at PR review to Koda's ruling, the gate record in the PR body states which reading the shipped fixture encodes, and the row may not silently ride the §9.8 default as if it were the ratified reading.
